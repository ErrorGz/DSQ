# Issue：氢需求展开时可能误用分馏塔配方并中断计算

## 建议标题

旧版计算器在展开氢需求时可能使用零净产出的分馏塔配方，导致“重氢分馏塔无法用于生产氢气”并中断计算

## 问题描述

旧版计算器 `index.html` 使用的 `Scripts/data.js` 中，配方选择存档 `settings_pf` 直接保存 `data` 数组的数字下标。`find(name, true)` 在使用存档配方时，没有先验证该配方是否属于目标物品，也没有验证抵消投入和产出后是否仍有目标物品的净产出。

当 `settings_pf["氢"]` 指向重氢分馏塔配方时，分馏塔配方为：

```text
氢 × 1 → 重氢 × 0.01 + 氢 × 0.99
```

抵消同名投入和产出后：

```text
氢净产出 = 0.99 - 1 = 0
剩余产物 = 重氢 × 0.01
```

因此分馏塔可以用于生产重氢，但不能作为“生产氢”的配方。当前实现会直接触发：

```text
重氢分馏塔无法用于生产氢气。
Error: 配方错误！可能是因为该配方净输出为负。
```

并中断整个需求展开过程。

## 影响范围

- 所有最终产生正氢净需求的物品，例如红矩阵、液氢燃料棒等，在氢配方存档无效时都可能触发。
- 默认粒子容器配方本身没有正氢净需求，因此单独生成粒子容器不一定触发；如果现场仍报错，应检查是否残留其他需求或使用了其他备选配方。
- 新建浏览器状态、清空配方存档后，粒子容器、红矩阵、液氢燃料棒通常可以正常计算。
- 该问题不是蓝图导出器直接抛出的错误，也不需要进入蓝图页面即可复现。

## 复现步骤

以下下标对应当前工作区的数据数组，数据数组变化后下标可能不同：

```js
// 当前 data 数组中：
// 31 = 轨道采集器（巨冰）制氢
// 187 = 重氢分馏塔
settings_pf["氢"] = 187;
saveSettingPf();

// 清空需求，加入一个必然需要氢的物品
xqs = [];
xqs.push({
  item: find("红矩阵", true),
  number: 60
});

update_all();
```

也可以直接在控制台调用最小的氢需求展开：

```js
settings_pf["氢"] = 187;
loadNumber("氢", 120);
```

预期修复前会立即出现目标提示并抛出异常。

## 预期行为

1. 分馏塔不应出现在“氢”的备选生产配方列表中。
2. 分馏塔仍应出现在“重氢”的备选生产配方列表中。
3. 如果旧存档、错位下标或越界下标导致氢配方无效，应自动清除该存档并回退到有效默认配方。
4. X 射线裂解等“投入氢、产出更多氢”的有效配方应继续保留。
5. 如果某个物品确实没有任何有效生产配方，应抛出包含该物品名的通用错误，而不是固定提示氢气问题。

## 实际行为

1. `getPfs("氢")` 只检查原始产物 `s[]` 中是否包含“氢”，因此会把分馏塔列为氢的备选配方。
2. `find()` 直接读取 `settings_pf[name]` 对应的数字下标，不验证配方归属和净产出。
3. 分馏塔抵消后氢净产出为 0，进入警告和异常分支。
4. 数字下标不是稳定配方 ID，数据数组插入、删除或重排后，旧存档可能指向另一条配方。

典型堆栈：

```text
Error: 配方错误！可能是因为该配方净输出为负。
    at get (Scripts/data.js)
    at find (Scripts/data.js)
    at loadNumber (Scripts/data.js)
    at loadNumber (Scripts/data.js)
    at expandDemand (Scripts/data.js)
    at update_all (Scripts/data.js)
```

## 根因分析

### 1. 备选配方列表没有做净产出校验

当前逻辑相当于：

```js
for (var i = 0; i < data.length; i++) {
  for (var j = 0; j < data[i].s.length; j++) {
    if (data[i].s[j].name == name) {
      // 直接加入备选配方
    }
  }
}
```

分馏塔的原始产物中确实包含氢，所以会被错误纳入。

### 2. 存档配方没有验证和回退

当前逻辑相当于：

```js
var pf = settings_pf[name];
if (pf) {
  return get(data[parseInt(pf)]);
}
```

它没有处理：

- 下标越界；
- 下标指向其他物品的配方；
- 下标指向零净产出的配方；
- `pf = 0` 被 falsy 判断跳过。

### 3. 净配平结果直接抛错

`find()` 在抵消后找不到目标物品时，没有尝试其他有效配方，而是立即警告并抛错，导致一次无效存档中断整个计算。

### 4. 两轮副产物抵扣不是直接根因

当前版本引入了“先统计副产盈余，再抵扣需求”的两轮展开逻辑，改变了 `loadNumber()` 的调用路径，但该逻辑不会自动把氢配方选择为分馏塔。直接根因仍是无效的配方选择及缺失校验。

## 建议修复方案

### 1. 抽取统一的配方净配平逻辑

在副本上补齐数量、抵消同名投入和产出，并使用浮点容差删除接近 0 的项，例如：

```js
var RECIPE_EPSILON = 1e-9;
```

只有目标物品的净产出大于容差时，才认为配方有效。

### 2. 用同一规则过滤 `getPfs()`

`getPfs(name)` 应只返回抵消后仍能净产出 `name` 的配方。这样：

- 氢列表不再包含分馏塔；
- 重氢列表仍包含分馏塔；
- X 射线裂解制氢等有效循环配方仍然保留。

### 3. 校验 `settings_pf` 并自动回退

`find()` 使用存档下标时，应验证：

- 下标是有限整数；
- 下标没有越界；
- 对应配方属于目标物品；
- 对应配方抵消后有目标物品的正净产出。

验证失败时删除 `settings_pf[name]`、持久化清理结果，并继续查找默认有效配方。

### 4. 将固定氢气错误改为通用错误

无效存档可以静默回退；只有确实不存在任何有效配方时，才抛出类似：

```text
没有可用于生产“某物品”的有效配方。
```

避免其他物品的配方问题被误报为氢气问题。

### 5. 长期改进：使用稳定配方标识

当前 `settings_pf` 保存数字下标，数据数组变化后容易错位。建议后续迁移为：

- 优先使用 `gameId`；
- 没有 `gameId` 时使用设备类型、排序后的投入和产物生成稳定 key；
- 读取旧数字下标时进行迁移和校验。

## 本地修复内容

本次已在本地工作区完成修复：

- `Scripts/data.js`
  - 新增统一的 `normalizeRecipe()` 净配平逻辑；
  - 新增 `RECIPE_EPSILON` 浮点容差；
  - 新增 `getRecipeForItem()`，统一判断配方是否能净产出目标物品；
  - `getPfs()` 过滤零净产出配方；
  - `find()` 验证存档下标，无效时清理并回退；
  - 移除写死的氢气警告，保留通用异常。
- `index.html`
  - 将 `Scripts/data.js` 的缓存参数从 `v=net12` 更新为 `v=net13`，避免浏览器继续使用旧脚本。

## 建议补充的回归测试

1. 全新状态下生成粒子容器、红矩阵、液氢燃料棒。
2. 强制保存分馏塔作为氢配方，确认自动回退且计算完成。
3. 保存越界下标和其他物品配方下标，确认自动回退。
4. 确认分馏塔仍能作为重氢配方使用。
5. 确认 X 射线裂解制氢等有效循环配方仍可选择。
6. 数据数组顺序变化后，旧存档不会导致崩溃。
7. 长期迁移为稳定配方 key 后，验证旧数字下标存档可正确迁移。

## 结论

该问题可以从配方净产出校验、无效存档回退和备选列表过滤三处修复。本地修复已完成并通过 Node 运行时验证；建议上游采用相同原则处理，并后续将 `settings_pf` 的数字下标迁移为稳定配方标识。
